# Architecture

Pixel Kingdom Rumble is a Unity 6 LTS project (2D URP, Input System, C#) for iPhone: portrait menus,
landscape gameplay, 60 FPS target. Everything is original; see [NAMING.md](NAMING.md) for renaming.

## Premise

Above a shattered world drift the Sunspire Isles, held aloft by the Tickworks, an ancient sky-machine whose
gears have begun to grind backward. Four heroes (Nova the comet-staff sky courier, Brick the stone guardian,
Luma the magnet-glove inventor, Rex Rollo the roller-skating lizard) collect Star Shards to keep the isles
aloft, and spar in the Skyforge Arena between expeditions. Their first big obstacle is the Clockwork Warden.

## Layers of code

```
PKR.Core     (Scripts/Core)     pure C#, no UnityEngine. Rules: combat math, Guard Pips, jump assist,
                                 movement math, save/settings data, economy, match rules, bot brain,
                                 enemy logic. Unit-tested by Unity EditMode AND by plain .NET (DotnetTests/).
PKR.Runtime  (Scripts/Runtime)  MonoBehaviours and ScriptableObjects that apply Core rules in the engine.
PKR.Editor   (Scripts/Editor)   PKR menu: project config, placeholder art, data assets, scene builders.
Tests        (Tests/EditMode, Tests/PlayMode)
```

Rule of thumb: if logic can be written without Unity types, it goes in Core and gets a .NET test.

## Key decisions

| Decision | Why |
|---|---|
| Scenes and data assets are **generated by editor commands** (PKR > Build …) | Reproducible from a clean clone; no hand-merged YAML; easy to rebuild after code changes |
| UI is **built in code** (`UIFactory`) instead of prefabs | Same reason; one theme switch for high contrast |
| **ScriptableObjects** for heroes, moves, enemies, levels, roster | Designers tune numbers without touching code |
| One **`FighterIntent`** for humans, CPUs and enemies | The same motor/attack code runs every fighter; bots can't cheat |
| **`ActionBuffer`** for presses, **`JumpAssist`** for coyote time + jump buffer | Forgiving touch controls |
| Custom **`PlatformerMotor2D`** on a dynamic Rigidbody2D | Tight feel with Unity physics for collisions; overrides for dashes, knockback, platforms |
| **Guard Pips** instead of percent damage in the arena | Original system: break 3 pips → *Exposed* → next heavy hit launches |
| **Object pools** (`PoolService`) for projectiles, pickups, puffs, enemies | No garbage spikes on iPhone |
| **Services** created before the first scene (`GameBootstrap`) | Save, settings, scenes, game state, audio, haptics available everywhere |
| Typed **`EventBus<T>`** | HUDs/menus react without hard references |
| Fixed step 1/60, frame rate 60 | Matches the performance target; frame data is in 60 Hz frames |
| Save as JSON with a backup file (`JsonFileStore`) | Crash-safe, readable, migratable (`SaveData.version`) |
| Economy is cosmetic-only | Design rule from the brief |

## Runtime flow

```
00_Boot (BootLoader) → 01_MainMenu → 02_CharacterSelect → SQ_SunspireMeadows_Test  (Story Quest)
                                                         → AC_Skyforge_Test         (Arena Clash)
```

`SceneLoader` switches orientation by scene prefix (`SQ_`/`AC_` = landscape) and resets game state.
`GameStateManager` holds Menu / Playing / Paused / Results; touch controls show only while Playing.

## Adding a hero (Phase 2 pattern)

Brick (Phase 2.1) was added this way:

1. Add a `CharacterDefinition` (+ `Moveset` of `MoveDefinition`s) in `DataAssets`. Movement, HP, weight, armor
   and Guard Pips are per hero; `MovementStats.airJumps` gives mid-air jumps.
2. Add a kit: a subclass of `HeroKitDefinition` that decides the air dodge velocity and tunes the dive.
   `HeroAbilities` runs every kit, so no new component is needed. Moves can have **super armor** frames.
3. Set `playableInThisBuild = true` in the roster. Character select, Story Quest (via `SelectedHeroLoader`),
   the arena and CPU fighters pick it up automatically.
